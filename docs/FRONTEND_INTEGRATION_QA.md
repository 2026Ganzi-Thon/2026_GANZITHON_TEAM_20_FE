# FE1·FE2 통합 및 배포 API 연동 검증

검증 기준: 2026-11-19. 최신 main be083ccc와 FE2 7a108fbb를 통합하고 별도 로컬 사본에서 검증한 수정사항을 반영했다. main의 FE1 변경 이력을 유지하며 App.jsx·Home.jsx 충돌을 해결했다.

## 변경 결과

- FE1 시작·홈·설정·걱정 입력·공개 시간·분석·봉인과 FE2 금고·상세·활동·기록·시연 라우트 연결.
- 공통 Axios/CSRF 저장소, 세션 변경 직렬화·이전 요청 취소, 다른 탭 인증 변경 정리와 401 안내 연결.
- S-16 안내, 최종 분석 실패 재시도·재입력, 429 대기 안내와 버튼 잠금. 응답 유실 재시도는 같은 키·문맥 유지.
- 기본 공개 시간은 서버 제안 및 브라우저 시간대 사용. 임의 최소 9시간 제한 제거.
- 원문·메모·불안도·재시도 본문은 히스토리/스토리지 대신 화면 메모리 초안에서 전달. 성공·안내 분기·세션 변경·전체 삭제 후 정리. 새로고침 시 입력이 사라졌으면 재입력하고 기존 요청 ID로 조회한다.
- summaryEdited 사용, 기록 상세 view 저장·활동 이력, 홈 활동 복귀와 다음 미열람 걱정 조건.
- 휴식은 serverTime·remainingSeconds·timeOver를 기준으로 복원하고 0초 재확인 후 명시적으로 완료.
- 삭제 202/응답 유실을 완료로 표시하지 않으며 동일 ID 수동 재확인에 대기 간격 적용. 204에서만 완료.
- 시연 권한 전 배지 숨김, 404 중립 안내, PLUS_24H 연결. 시연 키는 패널 메모리에만 보관.
- 푸시 권한 요청과 서비스워커 활성화 순서 보완. 이모지 코드포인트 길이 검사와 원문 공백 보존, 오류 로그 민감 정보 제외.

## 검사 결과와 범위

- npm run check:release: ESLint, 정책·계약·시간·초안 테스트 35개, production build, 예시 걱정 fixture 제외 검사 통과.
- 기존 별도 Chrome 실제 HTTPS 검사: 게스트 생성·재시도·봉인·공개·열람·수정·활동·평가·기록·삭제, 새로고침 세션 유지, S-16 모의 분기, REST 실제 180초 후 사용자 완료 확인.
- 오류 주입 브라우저: 429 대기·멱등 키 유지, CSRF 1회 재시도·동시 조회 합치기, 세션 변경 취소·두 탭 초안 정리, 삭제 202/404/204·재진입, 시연 계약, 휴식 서버 종료 확인, 다음 걱정 조건, 유니코드 500/501자 검사.
- 공개 대기는 합성 테스트 게스트의 publication PATCH로 수 초 뒤로 변경하는 API 보조 단계를 사용했다. 제품에 조기 열기를 추가하지 않았다.
- 백엔드 AI는 검증 당시 모의 분석 모드. 실제 Solar 품질·성능 검증을 의미하지 않는다.
- 백엔드 develop 1d01bd50의 Markdown 21개 중 프론트 관련 요구사항과 openapi.yaml 대조. 서버·DB·인프라 전체 감사가 아니다.

## 재현

1. npm ci
2. npm run check:release
3. 로컬 백엔드 개발 프로필: npm run dev (기본 proxy target http://127.0.0.1:8080)
4. 배포는 같은 HTTPS 출처에서 프론트 /와 API /api/v1을 분리한다. 운영 Secure·HttpOnly·SameSite 쿠키/CSRF를 완화하지 않는다. dist를 정적 파일로 배포하고 API 오류를 SPA로 변환하지 않는다.

## 남은 팀 검증

- 실제 iPhone Safari/Android Chrome의 푸시 실수신·절전 복귀·설치 조건.
- 실제 시연 키를 사용한 전체 프리셋·타임머신·회고/과거 경험 리허설.

- 앞선 초기 자동화에서 인증 문맥을 잃어 정리를 확인하지 못한 합성 걱정 1건(2eb5186e-93a5-49aa-96f3-6d6873526df6)은 운영자 확인/30일 만료 대상이다. 이후 검증용 게스트들은 금고 전체 삭제로 정리했다. 실제 개인정보를 사용하지 않았다.
