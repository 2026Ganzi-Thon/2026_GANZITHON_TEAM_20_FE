# Wooly Vault — 백엔드·AI 기술 스택 및 구현 현황

> 반영일: 2026-11-15 (한국 기준)
> 출처: 사용자가 공유한 백엔드·AI 파트 진행 보고.
> 이 문서는 팀 공유 내용을 보존한 자료이며, 저장소 코드·실제 서버·버전 지원 여부를 독립적으로 검증한 결과가 아니다.

## 현재 공유된 기술 구성

| 구분 | 공유된 기술 |
| --- | --- |
| 백엔드 | Java 21, Spring Boot 4.1.2, Spring Security |
| 데이터베이스·마이그레이션 | PostgreSQL 17, Flyway |
| 빌드·로컬 실행 | Gradle, Docker Compose |
| AI 서비스 | Python, FastAPI, Upstage Solar Mini 4 |
| 연결 구조 | 모바일 웹 → Spring 백엔드 → Python 내부 API → Solar API |

Spring 백엔드가 걱정 접수·금고·활동·평가·회고 API를 한 서버에서 제공하고, 인증과 기록 접근 검사를 공통으로 적용한다. Python 서비스는 AI 호출 및 응답 형식 검증을 맡는다. Spring이 결과를 PostgreSQL에 저장하며 모바일 웹은 Spring의 처리 상태를 조회한다.

기존 문서의 BE1·BE2 구분을 서로 다른 배포 서버 두 개로 단정하지 않는다. 이 보고에 따르면 API는 한 Spring 서버에서 제공된다. FE는 Python 내부 API·Solar API를 직접 호출하지 않는다.

## 인증·데이터 보호 — 공유된 구현

- 게스트 세션은 쿠키로 유지하고 DB에는 세션 토큰 해시를 저장한다.
- 데이터 변경 요청은 CSRF 토큰을 검사한다.
- 공개 시각이 지나도 작성한 게스트만 내용을 조회할 수 있다.
- 잠긴 동안에는 공개 예정 시각·상태 등 메타데이터만 반환한다.
- 원문·메모·AI 결과 등 민감 항목은 AES-256-GCM으로 암호화 저장한다.
- 걱정은 접수 후 30일에 만료된다.
- 개별 삭제·만료 시 접근을 차단하고 관련 기록을 정리한다.
- 전체 금고 삭제 시 게스트 세션도 폐기한다.

암호화 키 관리·백업 삭제·로그 수집 정책의 구체적인 구현은 이 보고만으로 확정하지 않는다. 암호화 저장이 외부 AI에 대한 전송 자체를 없애는 것은 아니며, 전달 범위 점검은 진행 중이다.

## FE2 개발에 반영할 사항

1. 모바일 웹의 API 호출 대상은 Spring 백엔드다. 외부 AI 키나 내부 서비스 인증을 FE에 넣지 않는다.
2. 백엔드 언어·DB·AI 프레임워크는 더 이상 미선정으로 안내하지 않고, 위 팀 공유 내용을 현재 기준으로 참고한다.
3. 실제 base URL, CORS, 쿠키 속성, CSRF 전달 방식, DTO·상태·오류 코드·삭제 완료 응답은 최신 코드와 확정 API를 확인한다. 스택 공유만으로 기존 draft 계약 전체가 구현 완료된 것으로 바꾸지 않는다.
4. 비동기 요청·상태 조회 구조를 유지한다. 관찰된 3.1~3.9초를 고정 대기시간이나 강제 타임아웃으로 사용하지 않는다.
5. AI 추천은 하나를 강조하되 네 도움 방식 선택을 유지한다. 공감 화면을 실시간 채팅으로 확대하지 않는다.
6. 금고·상세·기록에서 서버의 소유권·잠금·만료·삭제 검사를 전제로 한다.
7. 삭제·활동 완료·저장 성공의 정확한 판정은 응답 계약으로 확인한다. 로컬 연출로 성공을 대체하지 않는다.
8. 실제 위기 감지가 완성됐다고 가정하지 않고, 모의 검증과 실제 기능을 구분한다.
9. 기존 서비스 기획과 FE2 담당 범위를 유지한다. Figma 작업물은 변경하지 않는다.

## 팀 공유 원문

### 백엔드·AI 기술 스택 공유

- **백엔드** — Java 21, Spring Boot 4.1.2, Spring Security, PostgreSQL 17, Flyway, Gradle, Docker Compose
- **AI** — Python, FastAPI, Upstage Solar Mini 4

### 기술 스택 선정 이유 및 시스템 구성

- **Spring Boot · Spring Security** — 걱정 접수, 금고 조회, 활동·평가·회고 API를 한 서버에서 제공하고, 게스트 인증과 기록 접근 검사를 공통으로 적용하기 위해 사용했습니다.
- **PostgreSQL · Flyway** — 걱정·분석 결과·활동 기록의 관계를 관리하고, 팀원이 같은 DB 스키마를 사용할 수 있도록 변경 이력을 관리합니다.
- **Gradle · Docker Compose** — 팀원의 빌드 도구 버전과 로컬 PostgreSQL 실행 환경을 맞췄습니다.
- **Python · FastAPI · Solar API** — 한국어 걱정 분석과 모델 응답 검증을 별도 서비스에서 처리합니다. 서버에서 모델을 호출하므로 모바일에서는 브라우저만 있으면 됩니다.
- **연결 구조** — 모바일 웹 → Spring 백엔드 → Python 내부 API → Solar API. Spring이 결과를 PostgreSQL에 저장하고, 모바일 웹은 Spring에서 처리 상태를 조회합니다.

### AI 구현 방식

- 걱정을 제출하면 서버가 요청 ID를 먼저 반환하고 백그라운드에서 분석합니다. 현재 검증 구성에서 Solar에 보내는 데이터는 **걱정 원문**으로 제한했습니다.
- Solar는 **걱정 요약, 추천 도움 한 가지와 이유, 액션 3단계, 휴식 안내, 짧은 공감 문구**를 생성합니다. Python이 필수 항목과 형식을 검증하면 Spring이 결과를 암호화해 저장하고 걱정을 봉인합니다. 사용자는 AI가 추천한 도움 외에 다른 도움도 선택할 수 있습니다.
- 합성 입력 3건으로 실제 Solar 연동을 확인했고, 로컬에서 제출부터 완료 확인까지 약 **3.1~3.9초**가 걸렸습니다.

### 보안 및 개인정보 보호

- **인증** — 쿠키로 게스트 세션을 유지하고 DB에는 세션 토큰의 해시를 저장합니다. 데이터를 변경하는 요청은 CSRF 토큰을 검사합니다.
- **접근 제한** — 공개 시각이 지난 뒤에도 작성한 게스트만 내용을 볼 수 있습니다. 잠긴 동안에는 공개 예정 시각과 상태 같은 메타데이터만 반환합니다.
- **암호화·삭제** — 원문·메모·AI 결과 등 민감 항목은 **AES-256-GCM**으로 암호화해 저장합니다. 걱정은 접수 후 **30일**에 만료됩니다. 개별 삭제나 만료 시 접근을 차단하고 관련 기록을 정리하며, 금고 전체 삭제 시 게스트 세션도 폐기합니다.
