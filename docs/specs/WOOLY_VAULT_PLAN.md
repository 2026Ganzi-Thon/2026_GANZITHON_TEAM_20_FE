# 심야 걱정 금고 (Wooly Vault) 최종 기획안 (수정 내용 반영)

> 의견 반영 버전입니다. 추가 의견은 해당 항목에 댓글로 남겨주세요.
>
> 저장 기준: 2026-11-12 사용자 제공 기획안. 1~17장은 제공된 기획안이며, 마지막 부록은 사용자 담당 범위와 개발 참고 기준입니다.

## 1. 한 줄 소개

**잠들기 전 걱정을 짧게 금고에 맡기고, 다음 날 AI가 정리한 내용을 확인하며 나에게 필요한 도움을 직접 선택하는 멘탈 케어 모바일 웹 서비스**

밤에는 긴 대화 없이 걱정을 맡기고, 다음 날에는 파쇄·작은 행동·짧은 휴식·공감 메시지 중 원하는 방법으로 걱정을 다룹니다.

## 2. 기획 배경과 목적

잠자리에 누운 뒤에도 과제, 업무, 인간관계에 대한 생각이 이어져 쉬기 어려운 순간이 있습니다.

이때 고민을 길게 분석하거나 대화를 이어가기보다, 지금 떠오른 걱정을 짧게 정리하고 나중에 다시 살펴볼 수 있도록 돕고자 합니다.

서비스는 다음 세 가지 경험에 집중합니다.

- **밤에는 맡기기:** 걱정을 짧게 기록하고 이용을 마무리합니다.
- **다음 날에는 선택하기:** 걱정을 다시 살펴보고 필요한 도움을 직접 고릅니다.
- **다음 걱정에는 경험 활용하기:** 비슷한 상황에서 내가 선택했던 대응과 결과를 참고합니다.

수면 개선이나 치료 효과가 검증된 서비스로 표현하지 않으며, 일상적인 걱정 정리와 자기 돌아보기를 지원합니다.

## 3. 대상 사용자와 이용 상황

### 대상 사용자

학업·취업·업무·인간관계에 대한 걱정이 잠자리까지 이어지는 대학생과 사회초년생

### 핵심 이용 상황

- 잠들기 전 해야 할 일이 계속 떠오를 때
- 이미 지나간 일을 반복해서 생각할 때
- 지금 당장 해결하기 어려운 걱정을 잠시 내려놓고 싶을 때
- 다음 날 차분하게 걱정을 다시 살펴보고 싶을 때

## 4. 핵심 차별점

### ① 밤에 길게 대화시키지 않는 No-Chat 경험

걱정 입력과 봉인을 짧게 마칠 수 있도록 구성합니다. 실시간 채팅이나 피드 없이, 입력부터 봉인까지 1분 내 완료를 목표로 설계합니다.

실제 소요 시간은 테스트로 확인하며, 이미 달성한 성과처럼 표현하지 않습니다.

### ② 사용자가 도움 방식을 직접 선택

AI는 걱정을 정리하고 도움 방식을 추천합니다. 사용자는 정리 내용을 수정하거나 다른 도움을 선택할 수 있습니다.

### ③ 내 경험을 다음 걱정에 활용

삭제되지 않은 최근 기록에서 비슷한 걱정과 당시 선택한 대응을 보여줍니다. 사용자가 직접 도움이 되었다고 남긴 경험을 참고할 수 있도록 합니다.

### ④ 실제 삭제와 연결되는 파쇄

파쇄한 걱정은 원문뿐 아니라 관련 분석·활동 기록에서도 삭제하고, 이후 조회와 추천에서 제외합니다. 구체적인 삭제 범위와 백업 처리는 기능명세서의 정책을 따릅니다.

## 5. 전체 사용자 흐름

### 5-1. 처음 이용할 때

서비스 접속 → 게스트 이용 안내 → 걱정 입력

별도 회원가입 없이 시작하며, 같은 브라우저에서 기존 금고를 다시 이용할 수 있도록 합니다.

브라우저 데이터를 삭제하거나 다른 기기로 접속하면 기존 금고에 접근하기 어려울 수 있음을 안내합니다.

### 5-2. 밤 — 걱정 봉인

걱정 입력 → 불안도 체크 → 내일 확인할 것 한 줄 작성(선택) → 공개 시간 확인 → AI 분석·저장 → 금고 봉인

- 걱정은 한 번에 1개씩 등록합니다.
- AI 상세 분석은 공개 시간까지 보여주지 않습니다.
- 봉인 완료 후 다음과 같이 안내합니다.

> 맡겨두었어요. 이제 폰을 내려놓아도 돼요.

호흡 가이드는 선택 구현이며, 제공하는 경우에도 건너뛸 수 있습니다.

위기 대응 조건에 해당하면 일반 봉인을 중단하고 별도 도움 안내로 전환합니다.

### 5-3. 봉인 후 — 필요한 경우에만 재알림

봉인 완료 화면에 작은 보조 버튼을 제공합니다.

> 조금 뒤에 다시 알려주세요

사용자가 선택하면 **30분 뒤 / 1시간 뒤** 중 하나를 골라 알림을 예약할 수 있습니다.

- 기본 상태는 예약 없음입니다.
- 사용자가 요청한 경우에만 1회 발송합니다.
- 자동 반복이나 미확인 재촉 알림은 보내지 않습니다.
- 재알림을 눌러도 잠긴 걱정을 자동으로 열지 않습니다.

### 5-4. 아침 — 확인과 선택

금고 열기 → 걱정 선택 → AI 정리 확인·수정 → 불안도 재체크(선택) → 도움 방식 선택 → 실행·마무리

지난 걱정 회고는 대상 기록이 있을 때 최대 1개만 표시하며, 건너뛸 수 있습니다.

### 5-5. 다음 걱정 — 과거 경험 참고

비슷한 걱정이 다시 등록되면, 공개 후 확인 화면에서 관련된 과거 경험을 참고할 수 있도록 합니다.

밤의 입력·봉인 화면에는 지난 걱정 내용을 표시하지 않습니다.

## 6. 핵심 기능

### 6-1. 게스트 이용과 개인 금고

- 별도 로그인 없이 이용을 시작합니다.
- 브라우저에 발급한 인증 정보를 이용해 같은 브라우저의 금고에 접근합니다.
- 물리적인 기기를 확실하게 식별하는 방식으로 표현하지 않습니다.
- 게스트 이용에서도 서버의 인증과 기록 소유권 검사를 적용합니다.
- 다른 기기와의 동기화 및 계정 연결은 이번 핵심 범위에 포함하지 않습니다.

### 6-2. 걱정 입력과 불안도

- 걱정 내용과 불안도를 입력합니다.
- ‘내일 확인할 것’은 선택 메모로 제공합니다.
- 불안도는 1~5단계로 기록합니다.
- 공개 후에도 같은 척도로 상태를 기록할 수 있습니다.
- 불안도는 자기 보고 기록이며 진단 점수로 사용하지 않습니다.

### 6-3. AI 분석과 결과 잠금

- 걱정을 제출하면 AI가 내용을 정리하고 도움 방식을 추천합니다.
- 분석 결과는 설정한 공개 시각 이후에 확인할 수 있습니다.
- AI 정리와 추천은 사용자가 수정하거나 변경할 수 있습니다.
- AI가 사용자의 감정을 확정적으로 판단하거나 진단하는 표현은 사용하지 않습니다.

### 6-4. 금고 봉인

- 분석과 저장이 성공하면 금고 봉인 연출을 제공합니다.
- 공개 예정 날짜와 시간을 표시합니다.
- 이용을 마무리하는 문구와 선택형 재알림을 제공합니다.
- 저장에 실패한 상태를 봉인 완료로 표시하지 않습니다.

### 6-5. 도움 방식 4종

| 도움 방식 | 제공 경험 |
| --- | --- |
| 걱정 파쇄 | 삭제 범위를 확인한 뒤 걱정을 파쇄하고 관련 데이터를 삭제 |
| 10분 액션 | 지금 시도할 수 있는 작은 행동을 3단계로 제안 |
| 짧은 휴식 | 짧은 휴식 활동과 타이머 제공 |
| 그냥 들어줘 | 해당 걱정에 대한 짧은 공감 메시지 제공 |

AI 추천 하나를 강조하되 네 가지 선택지를 모두 제공합니다.

‘그냥 들어줘’는 실시간 대화가 아닌 한 번의 공감 메시지로 구성합니다.

### 6-6. 결과 기록과 회고

- 선택한 도움 방식과 활동 결과를 기록합니다.
- 불안도 전후 값이 모두 있을 때 변화를 보여줍니다.
- 지난 걱정은 ‘괜찮아짐 / 진행 중 / 걱정대로 됨’으로 회고할 수 있습니다.
- 도움 여부는 사용자가 직접 선택합니다.
- 활동 미완료나 중단에 불이익을 주지 않습니다.

## 7. 구현 범위

### 핵심 구현

- 게스트 이용과 사용자별 데이터 접근 제어
- 텍스트 걱정 입력과 불안도 체크
- 선택 메모
- AI 분석과 결과 잠금
- 위기 대응 분기와 도움 안내
- 금고 봉인 연출
- 공개 시간 설정과 선택형 공개 알림
- 봉인 후 30분·1시간 뒤 선택형 재알림
- 도움 방식 4종
- AI 정리 수정과 추천 변경
- 파쇄 및 관련 데이터 삭제
- 결과 기록과 과거 경험 확인
- 불안도 전후 비교
- 입력부터 봉인까지의 소요 시간 측정
- 시연 전용 타임머신
- 예외 처리와 보안 처리

### 선택 구현

1. 호흡 가이드
2. 캡처 OCR 입력
3. 사용자가 정한 취침 전 알림
4. 감정 패턴 리포트
5. 음성 입력
6. 이메일 대체 알림
7. 계정 연결과 기기 간 동기화

### 제외

| 기능 | 제외 이유 |
| --- | --- |
| 실시간 AI 대화 | 밤의 짧은 입력·봉인 경험에 집중 |
| 사용자 요청 없는 심야 알림 | 불필요한 접속 유도 방지 |
| 익명 편지·게시판 | 개인 금고 경험에 집중하고 운영 범위 제한 |
| 코인·상점·캐릭터 꾸미기 | 핵심 흐름 우선 구현 |
| 위치 기반 공간 추천 | 핵심 이용 상황과의 연결이 약함 |
| 파쇄 영상 외부 공유 | 개인적인 걱정 내용의 노출 방지 |
| 기상청 API·Document Parse | 핵심 기능 구현에 직접 필요하지 않음 |

## 9. 알림 운영 원칙

### 공개 알림

- 사용자가 선택한 경우에만 공개 시각에 발송합니다.
- 알림 권한은 사용자가 알림 받기를 선택했을 때 요청합니다.
- 같은 공개 시각의 걱정은 하나의 알림으로 묶습니다.
- 확인하지 않아도 반복해서 재촉하지 않습니다.

### 봉인 후 재알림

- 봉인 완료 화면에서 사용자가 직접 예약합니다.
- 30분 뒤 또는 1시간 뒤 중 하나를 선택합니다.
- 예약 확인·변경·취소가 가능하도록 합니다.
- 공개 알림 동의와 별도로 관리합니다.

### 공통

- 걱정 원문·요약·불안도를 알림에 포함하지 않습니다.
- 알림을 사용할 수 없어도 핵심 기능은 이용할 수 있습니다.
- 웹 푸시를 우선 구현하고 이메일은 추가 기능으로 분리합니다.
- 전송 환경에 따라 알림이 지연될 수 있으므로 정확한 도착을 보장하지 않습니다.

## 10. 안전 및 개인정보 원칙

### 위기 대응

- 별도로 정한 위기 대응 조건에 해당하면 일반 봉인 흐름을 중단합니다.
- 아침까지 기다리거나 재알림을 예약하도록 유도하지 않습니다.
- 공감 안내와 도움 연결 행동을 제공합니다.
- 감지 결과를 진단으로 표현하지 않습니다.
- 연결 정보와 상세 문구는 별도 위기 대응 정책에서 관리합니다.

### 개인정보와 데이터

- 서버에서 인증과 기록 소유권을 검사합니다.
- 걱정 원문과 민감한 파생 정보를 암호화해 저장합니다.
- 원문과 AI 응답을 일반 로그에 남기지 않습니다.
- 파쇄한 걱정은 관련 분석·결과·추천 데이터에서도 삭제합니다.
- 작성일로부터 30일이 지난 기록은 자동 삭제합니다.
- 백업과 외부 AI 제공자의 데이터 처리 범위는 실제 운영 조건에 맞게 안내합니다.
- 브라우저 정보 유실 시 기록 복구를 보장하지 않습니다.

## 11. 서비스 검증 계획

서비스 효과를 미리 단정하지 않고, 사용성과 이용 경험을 확인합니다.

| 확인할 내용 | 측정·확인 방법 |
| --- | --- |
| 짧게 맡길 수 있는가 | 입력 시작부터 봉인 완료까지 소요 시간 |
| 봉인 흐름을 이해하는가 | 입력·공개 시간 설정·봉인 과정의 이탈과 오류 |
| 다음 날 결과를 확인하는가 | 공개 이후 금고 확인 비율 |
| 원하는 도움을 고를 수 있는가 | AI 추천 변경 및 도움 선택 현황 |
| 도움이 되었다고 느끼는가 | 활동 후 선택형 도움 여부 응답 |
| 상태가 어떻게 달라졌는가 | 사용자가 입력한 불안도 전후 기록 |
| 알림이 부담스럽지 않은가 | 알림 해제·재알림 취소 및 사용자 의견 |

불안도 변화만으로 수면 개선이나 치료 효과를 주장하지 않습니다. 이용 분석에는 걱정 원문을 수집하지 않습니다.

## 14. 시연 구성

### 기본 시나리오

1. 걱정 한 줄과 불안도 입력
2. 공개 시각 확인 후 봉인
3. 봉인 완료와 선택형 재알림 소개
4. 시연용 타임머신으로 공개 시각 전환
5. AI 정리와 도움 선택 확인
6. 10분 액션 또는 파쇄 체험
7. 결과 기록과 과거 경험 활용 소개

### 시연 원칙

- 시연 모드임을 화면에 표시합니다.
- 실제 개인정보가 없는 예시를 사용합니다.
- 타임머신은 시연 권한이 있는 환경에서만 동작합니다.
- 네트워크 장애용 프리셋은 실제 AI 응답과 구분합니다.
- 오프라인 파쇄 체험은 선택형 부스 연출로 운영합니다.

## 부록 A. 사용자 담당 범위 — FE2

이 부록은 기획안 본문과 구분되는 사용자 지시 및 개발 참고 메모입니다.

- 프로젝트: 간지톤 / 심야 걱정 금고 (Wooly Vault)
- 사용자 역할: 프론트엔드 FE2
- 사용자가 제공한 역할표의 담당 항목: **금고·잠금 안내·상세·도움 활동·회고·기록·시연**
- 개발 작업은 위 FE2 범위에 한정합니다. 기획안의 전체 핵심 구현 목록이 사용자 개인의 개발 범위를 의미하지 않습니다.
- 담당 화면의 UI, 인터랙션, 상태 표시 및 API 연동을 구현합니다. 게스트 인증, AI 호출, 소유권 검사, 공개 시각 검증, 실제 삭제, 알림 예약 등 서버 기능은 백엔드와 연동할 사항입니다.
- 홈, 걱정 입력, 분석, 봉인 등 다른 파트의 구현을 임의로 맡지 않습니다. 화면 간 연결과 공동 컴포넌트의 세부 분담은 팀 문서에 따릅니다.

### FE2 구현 시 참고할 요구사항

| 담당 영역 | 기획안에서 확인된 요구사항 |
| --- | --- |
| 금고·잠금 안내 | 걱정 목록과 공개 가능 여부 표시, 공개 전 상세 분석 잠금, 공개 예정 날짜·시간 안내, 일반 이용 조기 열기 없음, 공개 전후 삭제 가능 |
| 상세 | 공개 후 AI 정리 확인·수정, 불안도 재체크 선택, 도움 추천 변경, 관련 과거 경험 확인 |
| 도움 활동 | 파쇄·10분 액션·짧은 휴식·그냥 들어줘 4종, 추천 하나 강조 및 전체 선택지 제공, 삭제 범위 확인, 휴식 타이머, 활동 중단 불이익 없음 |
| 회고 | 대상 기록이 있으면 최대 1개 표시 및 건너뛰기, 괜찮아짐·진행 중·걱정대로 됨 선택, 도움 여부 직접 응답 |
| 기록 | 선택한 도움 및 활동 결과 표시, 불안도 전후 값이 모두 있을 때만 변화 표시, 삭제·만료된 기록 제외 |
| 시연 | 시연 모드 표시, 예시 데이터 사용, 권한이 있는 환경의 타임머신 연동, 장애용 프리셋과 실제 AI 응답 구분 |

### 개발 참고 기준
